# Feather Browser v0.5 — Engine Hardening & Multi-Size Text

**Date:** 2026-10-21
**Status:** Approved

---

## Goal

Ship five targeted improvements to the v0.4 engine: patch a transitive TLS/HTTP security vulnerability, add a glyph cache that prevents per-paint font re-parsing, make font sizes actually render at the CSS-specified size, replace the exponential CSS descendant-matching algorithm with a linear one, and eliminate per-node ancestor-list allocations during style resolution.

---

## Architecture

No new subsystems. All changes are inside the existing `feather` crate. Five tasks execute sequentially because T3 and T4 both modify `style.rs`, and T2 depends on T1.

```
Cargo.toml          T0 — reqwest 0.11 → 0.12
src/engine/font.rs  T1 — glyph cache (OnceLock<Arc<Font>> + thread_local HashMap)
src/engine/render.rs T2 — per-item font_size in render_box; saturating_add
src/engine/style.rs T3 — O(D×S) iterative selector_matches
                    T4 — ancestors push/pop (no Vec allocation per node)
```

---

Rust 2021, gtk4 0.9, fontdue 0.9, reqwest 0.12 (was 0.11), glib 0.20. No new dependencies.

## Task 1 — Glyph Cache

### Problem

`FontMetrics::load(size: f32)` re-parses the 700KB embedded NotoSans font on every call. It is called once per layout pass, once per initial render, and once per scroll event. On a page that triggers frequent repaints this is a ~700KB memory parse on every frame.

### Design

Two-level cache, both inside `src/engine/font.rs`:

**Level 1 — parsed font shared across all sizes:**
```rust
use std::sync::{Arc, OnceLock};
static PARSED_FONT: OnceLock<Arc<fontdue::Font>> = OnceLock::new();

fn shared_font() -> Arc<fontdue::Font> {
    PARSED_FONT.get_or_init(|| {
        let bytes = include_bytes!("../../assets/NotoSans-Regular.ttf");
        Arc::new(fontdue::Font::from_bytes(bytes as &[u8], fontdue::FontSettings::default())
            .expect("embedded NotoSans is valid"))
    }).clone()
}
```

**Level 2 — per-size metrics cached per thread:**
```rust
thread_local! {
    static METRICS_CACHE: RefCell<std::collections::HashMap<u32, FontMetrics>> =
        RefCell::new(std::collections::HashMap::new());
}

impl FontMetrics {
    pub fn load_cached(size: f32) -> FontMetrics {
        let key = size.to_bits();
        METRICS_CACHE.with(|cache| {
            let mut map = cache.borrow_mut();
            if let Some(fm) = map.get(&key) {
                return fm.clone();
            }
            let fm = FontMetrics::load(size);
            map.insert(key, fm.clone());
            fm
        })
    }
}
```

**`FontMetrics` struct change** — `font: fontdue::Font` becomes `font: Arc<fontdue::Font>`. `FontMetrics` derives `Clone`. `FontMetrics::load` constructs from `shared_font()` instead of parsing from bytes.

**Callers updated** — every `FontMetrics::load(x)` call outside of tests becomes `FontMetrics::load_cached(x)`. Affected sites: `InlineFormattingContext::layout` in `layout.rs` and `Painter::paint` in `render.rs`.

### Interfaces produced

- `pub fn FontMetrics::load_cached(size: f32) -> FontMetrics` — new public function
- `FontMetrics` is now `Clone` (was not)
- `FontMetrics::load` still exists and still works — used by tests

### Tests

## Task 2 — Multi-Size Text Rendering

### Problem

`render_box` uses a single global `FontMetrics` (loaded at `Painter::paint`'s `font_size` parameter, always 16px) for every glyph on the canvas. `PlacedInlineItem.font_size` holds the per-item CSS font-size computed during layout but it is never used during render — all text paints at 16px regardless of CSS `font-size`.

### Design

**`src/engine/render.rs`** — inside `render_box`'s line-box rendering loop, replace the global `font` with a per-item lookup:

```rust
for item in &line.items {
    let item_font = crate::engine::font::FontMetrics::load_cached(item.font_size);
    let mut pen_x = (origin_x + item.x) as i32;
    for ch in item.text.chars() {
        let glyph = item_font.rasterize(ch);
        blit_glyph(canvas, &glyph, pen_x, baseline_y, item.color);
        pen_x = pen_x.saturating_add(item_font.advance_width(ch) as i32);
    }
}
```

Two changes land together here:
1. `item_font` replaces the outer `font` reference — per-item font size
2. `saturating_add` replaces `+=` — prevents i32 overflow on pathologically long lines

`Painter::paint(font_size: f32)` signature is unchanged — the parameter remains as the fallback size used by `render_text_scrolled` (the non-IFC text-node path).

The outer `let font = FontMetrics::load(font_size)` in `render_box` is kept for `render_text_scrolled` calls; only the IFC path (line_boxes non-empty) uses `item_font`.

## Task 3 — O(D×S) CSS Descendant Matching

### Problem

`selector_matches` for descendant combinators calls itself recursively for each ancestor position. For a selector with S compound parts and a DOM of depth D, matching costs O(D^S) — exponential in selector depth. With the existing cap of 32 selector levels, a pathological DOM triggers up to D^32 comparisons.

### Design

**`src/engine/style.rs`** — extract a `simple_matches` helper that tests tag/id/classes with no recursion, then rewrite `selector_matches` as an iterative loop:

```rust
fn simple_matches(elem: &ElementData, sel: &Selector) -> bool {
    if let Some(tag) = &sel.tag_name {
        if *tag != elem.tag_name { return false; }
    }
    if let Some(id) = &sel.id {
        if elem.attrs.get("id").map(String::as_str) != Some(id) { return false; }
    }
    for class in &sel.classes {
        let classes = elem.attrs.get("class").map(String::as_str).unwrap_or("");
        if !classes.split_whitespace().any(|c| c == class) { return false; }
    }
    true
}

fn selector_matches(elem: &ElementData, sel: &Selector, ancestors: &[ElementData]) -> bool {
    if !simple_matches(elem, sel) { return false; }
    let mut current = sel;
    let mut anc_slice = ancestors;
    while let Some((combinator, parent_sel)) = &current.ancestor {
        match combinator {
            Combinator::Child => {
                let Some(parent) = anc_slice.last() else { return false; };
                if !simple_matches(parent, parent_sel) { return false; }
                anc_slice = &anc_slice[..anc_slice.len() - 1];
            }
            Combinator::Descendant => {
                match anc_slice.iter().rposition(|a| simple_matches(a, parent_sel)) {
                    Some(i) => anc_slice = &anc_slice[..i],
                    None => return false,
                }
            }
        }
        current = parent_sel;
    }
    true
}
```

Greedy right-to-left scan: O(D × S) worst case. Correct for all practical CSS (no backtracking required on real web pages; the pathological counter-example requires adversarially crafted HTML+CSS).

The old `selector_matches` body is deleted entirely and replaced. `simple_matches` is a new private function.

## Task 4 — Eliminate ancestors.to_vec() Allocation

### Problem

`style_tree_depth` allocates a new `Vec<ElementData>` at every DOM node via `ancestors.to_vec()`. For a 1000-node DOM with average depth 10 this is 1000 Vec allocations and 10000 `ElementData` clones.

### Design

**`src/engine/style.rs`** — change `style_tree_depth` to take `ancestors: &mut Vec<ElementData>`. Push the current element before recursing into children; pop after. A single Vec grows to max DOM depth and is reused for all siblings.

```rust
fn style_tree_depth(
    node: &Node,
    stylesheet: &Stylesheet,
    depth: usize,
    ancestors: &mut Vec<ElementData>,
) -> StyledNode {
    if depth >= 512 {
        // depth cap — return unstyled node
        return StyledNode { node: node.clone(), properties: Default::default(), children: vec![] };
    }
    let mut styled = match &node.node_type {
        NodeType::Element(data) => {
            let props = specified_values(data, stylesheet, ancestors);
            StyledNode { node: node.clone(), properties: props, children: vec![] }
        }
        _ => StyledNode { node: node.clone(), properties: Default::default(), children: vec![] },
    };

    // Push current element for children's ancestor matching
    let pushed = if let NodeType::Element(data) = &node.node_type {
        ancestors.push(data.clone());
        true
    } else {
        false
    };

    styled.children = node.children.iter()
        .map(|c| style_tree_depth(c, stylesheet, depth + 1, ancestors))
        .collect();

    if pushed { ancestors.pop(); }
    styled
}
```

Public `style_tree` passes `&mut Vec::new()`:
```rust
pub fn style_tree(root: &Node, stylesheet: &Stylesheet) -> StyledNode {
    style_tree_depth(root, stylesheet, 0, &mut Vec::new())
}
```

`specified_values` and `selector_matches` signatures are unchanged — they take `&[ElementData]`; the caller passes `ancestors.as_slice()`.

### Tests

No new test file — the existing style tests in `tests/engine_css_test.rs` fully exercise this code path. A regression here produces wrong styling (colors, display values) that the existing tests catch. Verify: all existing tests pass without modification.

### Commit

```
fix(engine): eliminate per-node ancestors.to_vec() allocation in style_tree
```

# Feather Browser v0.6 — Glyph Bitmap Cache & Advance Width Bundle

**Date:** 2026-10-21
**Status:** Approved

---

## Goal

Complete the three-level font cache so that after warmup every paint renders
without calling fontdue's rasterizer, and every render-loop character advance
resolves from the already-fetched cached glyph rather than a second
`font.metrics()` call.

---

## Background

v0.5 established two cache levels in `src/engine/font.rs`:

| Level | Key | What's cached | Added |
|-------|-----|--------------|-------|
| 1 | — | Parsed `Arc<Font>` (`OnceLock`) | v0.5 T1 |
| 2 | `size.to_bits(): u32` | `FontMetrics` per size | v0.5 T1 |

What remained deferred (v0.5 "Deferred to v0.6"):

> Per-glyph advance cache inside `FontMetrics` (rasterize is called per
> character, not cached)

v0.6 adds Level 3 and bundles the advance width into the cached entry.

---

## Architecture

No new subsystems. All changes are inside the existing `feather` crate, across
two files that execute sequentially (T2 depends on T1's new API).


## Task 1 — Glyph Bitmap Cache in font.rs

### Problem

`FontMetrics::rasterize(ch)` calls `self.font.rasterize(ch, self.size)` on
every invocation. fontdue's rasterizer performs sub-pixel anti-aliasing on each
call. The render loop in `render.rs` calls `rasterize` once per character per
paint frame, then calls `advance_width(ch)` separately — a second
`font.metrics(ch, size)` per character.

### Design

**Extend `GlyphBitmap`** — add `advance_width: f32` so both the bitmap and the
advance metric travel together:

```rust
pub struct GlyphBitmap {
    pub pixels: Vec<u8>,
    pub width: usize,
    pub height: usize,
    pub bearing_x: i32,
    pub bearing_y: i32,
    pub advance_width: f32,   // new field; populated by rasterize
}
```

**Update `rasterize`** — fill the new field from `metrics.advance_width`:

```rust
pub fn rasterize(&self, ch: char) -> GlyphBitmap {
    let (metrics, pixels) = self.font.rasterize(ch, self.size);
    GlyphBitmap {
        pixels,
        width: metrics.width,
        height: metrics.height,
        bearing_x: metrics.xmin,
        bearing_y: metrics.ymin + metrics.height as i32,
        advance_width: metrics.advance_width,
    }
}
```

**Add Level-3 thread-local cache:**

```rust
thread_local! {
    static GLYPH_CACHE: RefCell<HashMap<u64, Arc<GlyphBitmap>>> =
        RefCell::new(HashMap::new());
}
```

Cache key: `(ch as u64) << 32 | self.size.to_bits() as u64`

A Rust `char` is at most 21 bits (U+10FFFF); `f32::to_bits()` is 32 bits. The
combined u64 key is collision-free.

**Add `rasterize_cached`:**

```rust
pub fn rasterize_cached(&self, ch: char) -> Arc<GlyphBitmap> {
    let key = (ch as u64) << 32 | self.size.to_bits() as u64;
    GLYPH_CACHE.with(|cache| {
        let mut map = cache.borrow_mut();
        if let Some(g) = map.get(&key) {
            return g.clone();
        }
        let g = Arc::new(self.rasterize(ch));
        map.insert(key, g.clone());
        g
    })
}
```

`rasterize` (public, unchanged signature) is kept for direct use in tests.
`rasterize_cached` is the hot path for the renderer.

### What stays the same

`advance_width(&self, ch: char) -> f32` and `measure_str` are **not changed**.
They continue to call `font.metrics(ch, size).advance_width` during layout.
Layout does not need bitmaps; fontdue's own metric lookup is fast; and warming
the glyph bitmap cache during layout (before any paint) is unnecessary.

### Interfaces produced

- `GlyphBitmap::advance_width: f32` — new public field
- `pub fn FontMetrics::rasterize_cached(&self, ch: char) -> Arc<GlyphBitmap>` — new

### Tests

Append to `tests/engine_font_test.rs` (all under `#[cfg(feature = "feather-renderer")]`):

```rust
#[test]
fn test_glyph_advance_width_field_populated() {
    let fm = FontMetrics::load(16.0);
    let g = fm.rasterize('A');
    let expected = fm.advance_width('A');
    assert!((g.advance_width - expected).abs() < 0.5,
        "GlyphBitmap.advance_width {:.2} should match advance_width('A') {:.2}",
        g.advance_width, expected);
}

#[test]
fn test_rasterize_cached_same_as_uncached() {
    let fm = FontMetrics::load(16.0);
    let uncached = fm.rasterize('B');
    let cached = fm.rasterize_cached('B');
    assert_eq!(cached.width, uncached.width);
    assert_eq!(cached.height, uncached.height);
    assert_eq!(cached.bearing_x, uncached.bearing_x);
    assert_eq!(cached.pixels, uncached.pixels);
    assert!((cached.advance_width - uncached.advance_width).abs() < 0.01);
}

#[test]
fn test_rasterize_cached_is_idempotent() {
    let fm = FontMetrics::load(16.0);
    let first = fm.rasterize_cached('C');
    let second = fm.rasterize_cached('C');
    // Same Arc — pointer equality confirms cache hit
    assert!(Arc::ptr_eq(&first, &second));
}

#[test]
fn test_cache_advance_width_matches_metrics() {
    let fm = FontMetrics::load(24.0);
    let glyph = fm.rasterize_cached('M');
    let from_metrics = fm.advance_width('M');
    assert!((glyph.advance_width - from_metrics).abs() < 0.5,
        "cached advance {:.2} vs metrics {:.2}", glyph.advance_width, from_metrics);
}
```

## Task 2 — Renderer Uses Glyph Cache

### Problem

`render_box` in `render.rs` calls `item_font.rasterize(ch)` (uncached) for
every character on every paint, then calls `item_font.advance_width(ch)` for a
second metrics lookup for the same character. After T1, both calls can be
replaced by a single `rasterize_cached` and direct field access.

### Design

**Inside the IFC render loop in `render_box`:**

```rust
// before
for ch in item.text.chars() {
    let glyph = item_font.rasterize(ch);
    blit_glyph(canvas, &glyph, pen_x, baseline_y, item.color);
    pen_x = pen_x.saturating_add(item_font.advance_width(ch) as i32);
}

// after
for ch in item.text.chars() {
    let glyph = item_font.rasterize_cached(ch);                     // Arc<GlyphBitmap>
    blit_glyph(canvas, &glyph, pen_x, baseline_y, item.color);     // &GlyphBitmap via Deref
    pen_x = pen_x.saturating_add(glyph.advance_width as i32);      // from cached glyph — no second lookup
}
```

`blit_glyph` signature is unchanged — it takes `&GlyphBitmap`, which
`Arc<GlyphBitmap>` satisfies through `Deref`. No other callers of `rasterize`
or `advance_width` exist in `render.rs`.

### What stays the same

`blit_glyph`, `render_background_scrolled`, `render_borders_scrolled`,
`render_text_scrolled`, `get_color` — all unchanged.

### Interfaces consumed

- `FontMetrics::rasterize_cached(&self, ch: char) -> Arc<GlyphBitmap>` — from T1
- `GlyphBitmap::advance_width: f32` — from T1

### Tests

Append to `tests/engine_render_test.rs` (under `#[cfg(feature = "feather-renderer")]`):

```rust
#[test]
fn test_render_with_cached_glyphs_does_not_panic() {
    use feather::engine::{
        dom::{Node, NodeType, ElementData},
        style::style_tree,
        layout::{LayoutEngine, Rect},
        render::Painter,
    };
    use std::collections::HashMap;
    // Minimal styled tree: one block with inline text children
    let text_node = Node {
        node_type: NodeType::Text("Hello cache".into()),
        children: vec![],
    };
    let mut attrs = HashMap::new();
    attrs.insert("id".to_string(), "root".to_string());
    let elem = Node {
        node_type: NodeType::Element(ElementData {
            tag_name: "div".into(),
            attrs,
        }),
        children: vec![text_node],
    };
    let css = feather::engine::css::CssParser::parse(
        "div { display: block; font-size: 16px; color: #1e1e1e; }",
    );
    let styled = style_tree(&elem, &css);
    let layout = LayoutEngine::build(&styled, 800.0);
    let viewport = Rect { x: 0.0, y: 0.0, width: 800.0, height: 600.0 };
    // Must not panic — smoke test for the cached render path
    let canvas = Painter::paint(&layout, viewport, 16.0);
    assert_eq!(canvas.width, 800);
    assert_eq!(canvas.height, 600);
}
```

## Goal

Add test coverage for CSS selector matching. Class (`.foo`), id (`#bar`), descendant (`div p`), and child (`div > p`) selectors are already implemented in `style.rs` but have never been tested. This patch closes that gap.

No new code in `src/` is expected; if any test reveals a bug, the fix is included in this patch.

## Feature 1 — CSS selector tests

### Problem

`selector_matches` in `style.rs` handles class, id, descendant, and child combinators. There are zero tests verifying this. A regression in selector matching would go undetected until visual output breaks.

### Design

Add four tests in `tests/engine_style_test.rs`. Each test builds a small DOM + CSS sheet, calls `style_tree`, and asserts that the correct property value appears on the targeted node and not on non-matching nodes.

Helper needed: `find_node_by_tag` — recurse through a `StyledNode` tree and return the first node whose element tag matches.

### Tests

- **`test_class_selector_matches`**: HTML `<div><p class="foo">x</p><p>y</p></div>`, CSS `.foo { color: red; }` — the `p.foo` node has `color: red`; the plain `p` does not.
- **`test_id_selector_matches`**: HTML `<div><p id="bar">x</p><p>y</p></div>`, CSS `#bar { color: blue; }` — only the `#bar` node has `color: blue`.
- **`test_descendant_combinator`**: HTML `<div><p>inside</p></div><p>outside</p>`, CSS `div p { color: green; }` — `p` inside `div` gets `color: green`; outer `p` does not.
- **`test_child_combinator`**: HTML `<div><p><span>deep</span></p></div>`, CSS `div > p { color: orange; }` — direct child `p` gets `color: orange`; grandchild `span` does not.

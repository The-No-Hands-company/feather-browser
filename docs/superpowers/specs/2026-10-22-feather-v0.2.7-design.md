## Feature 1 — Named color expansion

### Problem

`CssColor::from_keyword` currently returns `None` for any color not in its 11-entry list. Pages that use `color: navy`, `background-color: teal`, or `border: 1px solid coral` silently get no color because the `Value::Keyword("navy")` falls through in render's `get_color`. This makes real pages look wrong.

### Design

Add the following entries to the `match` arm in `from_keyword`. Values are the CSS spec sRGB values.

```
"cyan" | "aqua"         => (0, 255, 255)
"magenta" | "fuchsia"   => (255, 0, 255)
"lime"                  => (0, 255, 0)
"navy"                  => (0, 0, 128)
"teal"                  => (0, 128, 128)
"maroon"                => (128, 0, 0)
"olive"                 => (128, 128, 0)
"silver"                => (192, 192, 192)
"coral"                 => (255, 127, 80)
"salmon"                => (250, 128, 114)
"skyblue"               => (135, 206, 235)
"tomato"                => (255, 99, 71)
"indigo"                => (75, 0, 130)
"violet"                => (238, 130, 238)
"brown"                 => (165, 42, 42)
"tan"                   => (210, 180, 140)
"lightgray" | "lightgrey" => (211, 211, 211)
"darkgray"  | "darkgrey"  => (169, 169, 169)
"whitesmoke"            => (245, 245, 245)
"beige"                 => (245, 245, 220)
"gold"                  => (255, 215, 0)
"crimson"               => (220, 20, 60)
"hotpink"               => (255, 105, 180)
"lightblue"             => (173, 216, 230)
"lightgreen"            => (144, 238, 144)
"lightyellow"           => (255, 255, 224)
"darkblue"              => (0, 0, 139)
"darkgreen"             => (0, 100, 0)
"darkred"               => (139, 0, 0)
"darkorange"            => (255, 140, 0)
"deeppink"              => (255, 20, 147)
"deepskyblue"           => (0, 191, 255)
"forestgreen"           => (34, 139, 34)
"limegreen"             => (50, 205, 50)
"mediumblue"            => (0, 0, 205)
"midnightblue"          => (25, 25, 112)
"royalblue"             => (65, 105, 225)
"slategray" | "slategrey" => (112, 128, 144)
"steelblue"             => (70, 130, 180)
```

All `a: 255` (fully opaque). No new struct fields or enum variants needed.

### Tests

In `tests/engine_css_test.rs`, append a module with:

- `test_named_colors_css_level1`: verify `navy`, `teal`, `maroon`, `olive`, `silver`, `lime` all parse to their correct RGB values via `CssParser::parse_value`
- `test_named_colors_aliases`: verify `cyan` == `aqua`, `magenta` == `fuchsia`, `gray` == `grey`, `lightgray` == `lightgrey`, `darkgray` == `darkgrey`, `slategray` == `slategrey`
- `test_named_colors_extended`: spot-check `coral`, `crimson`, `gold`, `hotpink`, `tomato`, `indigo`

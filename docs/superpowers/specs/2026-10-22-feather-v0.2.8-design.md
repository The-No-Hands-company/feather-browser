## Goal

Two engine features:

1. **`vw` and `vh` viewport units** — resolve `width: 50vw` and `height: 100vh` to pixel lengths at layout time.
2. **`min-width` / `max-width` constraints** — clamp a block's computed width to its `min-width` / `max-width` CSS values.

## Feature 1 — `vw` / `vh` viewport units

### Problem

`Unit` enum has `Px`, `Em`, `Rem`, `Percent` — no `Vw` or `Vh`. A CSS rule `width: 50vw` parses as `Value::Keyword("50vw")` and is ignored by layout's `calculate_block_width` explicit-width check. Viewport-relative sizing is completely non-functional.

### Design

**`src/engine/css.rs`** — add two new variants to `Unit`:

```rust
pub enum Unit {
    Px,
    Em,
    Rem,
    Percent,
    Vw,
    Vh,
}
```

In `parse_value`, add before the bare-number check (longest suffix first, after `rem`):

```rust
if let Some(rest) = s.strip_suffix("vw") {
    if let Ok(n) = rest.trim().parse::<f32>() { return Value::Length(n, Unit::Vw); }
}
if let Some(rest) = s.strip_suffix("vh") {
    if let Ok(n) = rest.trim().parse::<f32>() { return Value::Length(n, Unit::Vh); }
}
```

**`src/engine/layout.rs`** — thread `viewport_height` through the layout engine:

Change `LayoutEngine::build` signature from:
```rust
pub fn build(root: &StyledNode, containing_width: f32) -> LayoutBox
```
to:
```rust
pub fn build(root: &StyledNode, containing_width: f32) -> LayoutBox
// internally uses viewport_height = 600.0 default
```

Add a private `build_with_viewport` entry:
```rust
pub fn build_with_viewport(root: &StyledNode, containing_width: f32, viewport_height: f32) -> LayoutBox
```
`build` calls `build_with_viewport(root, containing_width, 600.0)`.

Pass `viewport_height` down to `calculate_block_width` and `calculate_block_position` (add it as a parameter to each).

In `calculate_block_width`, resolve `vw` and `vh` widths:
```rust
Some(Value::Length(n, Unit::Vw)) => Some(n / 100.0 * containing.content.width),
Some(Value::Length(n, Unit::Vh)) => Some(n / 100.0 * viewport_height),
```

In `calculate_block_position`, if an explicit `height` is `vw` or `vh`:
```rust
Some(Value::Length(n, Unit::Vh)) => { lb.dimensions.content.height = n / 100.0 * viewport_height; }
Some(Value::Length(n, Unit::Vw)) => { lb.dimensions.content.height = n / 100.0 * containing.content.width; }
```

**Existing callers:** `LayoutEngine::build` signature is unchanged for callers that don't know the viewport height. `build_with_viewport` is the future API.

### Tests

In `tests/engine_layout_test.rs`:

- `test_vw_width_resolves`: `<div style="width: 50vw;">` with containing_width=800 → `content.width == 400.0`
- `test_vh_height_resolves`: `<div style="height: 100vh;">` via `build_with_viewport(..., 600.0)` → `content.height == 600.0`

## Feature 2 — `min-width` / `max-width`

### Problem

`calculate_block_width` computes a width from the containing block or explicit `width:` but never consults `min-width` or `max-width`. A responsive layout that relies on `max-width: 800px` or `min-width: 200px` ignores those constraints entirely.

### Design

In `calculate_block_width` in `src/engine/layout.rs`, after the `width` is computed (and before setting `lb.dimensions.content.width`):

```rust
// min-width clamps up
if let Some(Value::Length(min, Unit::Px)) = styled.properties.get("min-width") {
    width = width.max(*min);
}
// max-width clamps down
if let Some(Value::Length(max, Unit::Px)) = styled.properties.get("max-width") {
    width = width.min(*max);
}
```

Also handle `Unit::Percent` for both:
```rust
if let Some(Value::Length(min_pct, Unit::Percent)) = styled.properties.get("min-width") {
    width = width.max(min_pct / 100.0 * cw);
}
if let Some(Value::Length(max_pct, Unit::Percent)) = styled.properties.get("max-width") {
    width = width.min(max_pct / 100.0 * cw);
}
```

### Tests

In `tests/engine_layout_test.rs`:

- `test_min_width_clamps_up`: `<div style="width: 50px; min-width: 200px;">` with containing_width=800 → `content.width == 200.0`
- `test_max_width_clamps_down`: `<div style="max-width: 300px;">` with containing_width=800 (auto fill → 800) → `content.width == 300.0`
- `test_min_max_width_no_effect_when_within`: `<div style="width: 400px; min-width: 100px; max-width: 600px;">` → `content.width == 400.0`

**Version:** 0.2.9

## Goal

Two engine features:

1. **`display: none`** — elements with `display: none` produce no layout box and are invisible.
2. **`overflow: hidden`** — child boxes that extend outside a parent with `overflow: hidden` are not rendered.

## Feature 1 — `display: none`

### Problem

`build_layout_tree` in `layout.rs` always creates a layout box for every styled node. An element with `display: none` appears in the layout tree with zero dimensions, but it still occupies space in the parent's child list and its children recurse. CSS semantics require it to produce no box at all.

### Design

In `build_layout_tree` in `src/engine/layout.rs`, before determining the `BoxType`, check for `display: none`:

```rust
// display: none → produce no box
if matches!(
    styled.properties.get("display"),
    Some(Value::Keyword(k)) if k == "none"
) {
    return None;
}
```

Change `build_layout_tree` return type from `LayoutBox` to `Option<LayoutBox>`.

Update `LayoutEngine::build` and any recursive call sites to handle `None` by skipping the child:

```rust
fn build_layout_tree(styled: &StyledNode) -> Option<LayoutBox> { ... }
```

In the children loop:
```rust
for child in &styled.children {
    if let Some(child_box) = build_layout_tree(child) {
        lb.children.push(child_box);
    }
}
```

`LayoutEngine::build` unwraps the root:
```rust
pub fn build(root: &StyledNode, containing_width: f32) -> LayoutBox {
    build_layout_tree(root).unwrap_or_default()
}
```

### Tests

In `tests/engine_layout_test.rs`:

- `test_display_none_produces_no_box`: HTML `<div><p style="display: none;">hidden</p><p>visible</p></div>` — layout tree must contain no box with tag `p` that has `display: none`; `visible` p must still appear.
- `test_display_none_children_not_laid_out`: HTML `<div style="display: none;"><p>child</p></div>` — the layout tree's root's children must not include the hidden div.

## Feature 2 — `overflow: hidden`

### Problem

`render_box` recurses into all children regardless of whether they extend beyond their parent. A parent with `overflow: hidden` and children that overflow should not render the overflowing portions. Currently there is no clipping mechanism.

### Design

The simplest correct approach: when a box has `overflow: hidden`, skip rendering any child whose entire `border_box` lies OUTSIDE the parent's `border_box`. Children that are fully inside or partially overlapping are still rendered (we do not do sub-pixel clipping — that requires a canvas scissor API which doesn't exist yet).

In `render_box` (the `#[cfg(feature = "feather-renderer")]` version) in `src/engine/render.rs`, after rendering the current box's background and borders, before recursing into children:

```rust
let overflow_hidden = has_overflow_hidden(lb);
for child in &lb.children {
    if overflow_hidden {
        let pb = lb.dimensions.border_box();
        let cb = child.dimensions.border_box();
        // skip only if child is fully outside parent in any direction
        let outside = cb.x + cb.width <= pb.x
            || cb.x >= pb.x + pb.width
            || cb.y + cb.height <= pb.y
            || cb.y >= pb.y + pb.height;
        if outside { continue; }
    }
    render_box(canvas, child, font, scroll_y, depth + 1);
}
```

Add a helper:
```rust
fn has_overflow_hidden(lb: &LayoutBox) -> bool {
    match &lb.box_type {
        BoxType::Block(s) | BoxType::Inline(s) =>
            matches!(s.properties.get("overflow"), Some(Value::Keyword(k)) if k == "hidden"),
        BoxType::Anonymous => false,
    }
}
```

Apply the same pattern in `render_box_plain` (the non-renderer path) — same logic, no `scroll_y`.

**Limitation documented in Known Limitations:** partially-overflowing children are not clipped at the pixel level — a child that straddles the edge of an `overflow: hidden` parent renders fully. Full sub-pixel clipping requires a canvas scissor rect, planned for a later release.

### Tests

In `tests/engine_render_test.rs` (`#[cfg(feature = "feather-renderer")]`):

- `test_display_none_produces_no_pixels`: render a page with `<div style="display: none; background-color: red;">` — canvas must have zero red pixels.
- `test_overflow_hidden_clips_child`: render a parent `<div style="width: 10px; height: 10px; overflow: hidden; background-color: white;">` containing `<div style="width: 200px; height: 200px; background-color: red;">` — the canvas at pixels (100, 100) must NOT be red (child fully outside parent → skipped).

# Feather Browser v0.7 — CSS Property Inheritance

**Date:** 2026-10-22
**Status:** Approved

---

## Goal

Make `color` and `font-size` propagate from parent to child nodes in the
style tree so that child elements without explicit CSS rules render with
their ancestor's values. Resolve `em` units relative to the parent's
computed `font-size`.

---

## Background

v0.6 completed the three-level font cache. The remaining highest-impact
correctness gap is CSS inheritance: without it, any element that relies on
inheriting its parent's `color` or `font-size` renders with the engine's
hardcoded fallbacks (`{30,30,30}` near-black and `16px`) regardless of
what the author wrote.

---

## Architecture

Two files change. Everything else is untouched.

| File | Change |
|------|--------|
| `src/engine/style.rs` | Inheritance + `em` resolution in `style_tree_depth()` |
| `src/engine/layout.rs` | Thread `parent_color` into `collect_inline_text()` for Anonymous boxes |

---

## Design

### Inheritable properties

Only two properties are in scope for v0.7:

| Property | CSS inherited? |
|----------|---------------|
| `color` | yes |
| `font-size` | yes |

All other properties remain non-inherited (resolved from CSS rules only).

### Inheritance algorithm (`style.rs`)

`style_tree_depth()` gains a `parent_props: &PropertyMap` parameter.

After `specified_values()` produces the CSS-matched `map` for a node, a
second pass applies inheritance:

```
const INHERITABLE: &[&str] = &["color", "font-size"];

for prop in INHERITABLE {
    if !map.contains_key(*prop) {
        if let Some(v) = parent_props.get(*prop) {
            map.insert(prop.to_string(), v.clone());
        }
    }
}
```

### `em` resolution (`style.rs`)

After the inheritance pass, resolve `em` units:

```
if let Some(Value::Length(n, Unit::Em)) = map.get("font-size") {
    let n = *n;
    let parent_px = match parent_props.get("font-size") {
        Some(Value::Length(px, Unit::Px)) => *px,
        _ => 16.0,
    };
    map.insert("font-size".to_string(), Value::Length(n * parent_px, Unit::Px));
}
```

Because each node resolves `em → px` before passing its `properties` down
to children, the parent value is always in `px` by the time a child reads it.

### Recursion

```rust
// current node's resolved properties become the parent for its children
for c in &root.children {
    children.push(style_tree_depth(c, stylesheet, depth + 1, ancestors, &properties));
}
```

The public entry point passes `&PropertyMap::new()` as the root's parent
(no inherited values above the document root).

### Anonymous box color (`layout.rs`)

`collect_inline_text()` already receives `parent_font_size: f32`. It gains
a `parent_color: CssColor` companion:

```rust
fn collect_inline_text(
    children: &[LayoutBox],
    parent_font_size: f32,
    parent_color: CssColor,
) -> Vec<InlineText>
```

`layout_block()` extracts the block's resolved color from `s.properties`
(same pattern as the existing font-size extraction, default `CssColor::BLACK`)
and passes it to `collect_inline_text`. Anonymous text boxes use
`parent_color` instead of the hardcoded `{30, 30, 30}`.

`collect_text_from_layout_children()` already receives and threads `color`
through — no change needed there.

## Testing

New file: `tests/engine_style_test.rs`, all tests under
`#[cfg(feature = "feather-renderer")]` inside `mod style_tests`.

| # | Test name | What it proves |
|---|-----------|----------------|
| 1 | `test_color_inherited_by_child` | `div { color: red }` + `<div><span></span></div>` → `span` properties contain red |
| 2 | `test_font_size_inherited_by_child` | `p { font-size: 20px }` + `<p><em></em></p>` → `em` node gets `font-size: 20px` |
| 3 | `test_explicit_child_overrides_inherited` | Parent `color: red`, child `color: blue` → child keeps blue |
| 4 | `test_em_resolves_relative_to_parent` | `body { font-size: 20px }` + `p { font-size: 0.5em }` + `<body><p></p></body>` → `p` gets `font-size: 10px` |
| 5 | `test_deeply_nested_inherits_from_grandparent` | `div { color: blue }` + three nesting levels → innermost child has blue |
| 6 | `test_root_with_no_parent_does_not_panic` | Element with no matching rules, `style_tree()` returns without panic and properties are empty |

## Deferred to v0.8

- `text-align: center / right`
- `<img>` placeholder rendering
- `StyledNode::node: Arc<Node>` (O(1) style-tree clone)
- `pen_x` subpixel drift (`advance_width as i32` vs `f32` layout widths)
- Unbounded glyph cache (LRU cap)
- Additional inheritable properties (`line-height`, `font-family`, etc.)
- `rem` unit resolution (requires root font-size tracking)

# Feather Browser v0.8 — Rendering Correctness + text-align

**Date:** 2026-10-22
**Status:** Approved

---

## Goal

Two micro-fixes eliminate known correctness defects left over from v0.6/v0.7,
and `text-align: center / right` adds the first user-visible layout alignment
feature.

---

## Background

v0.7 completed CSS inheritance and em resolution. Three deferred defects remain
in scope:

1. **`pen_x` subpixel drift** — `render.rs` accumulates pen position as `i32`
   per glyph, truncating the fractional part of `advance_width` on every
   character. Over a word, this causes ~1 px gap between characters that grows
   with string length.

2. **`DEFAULT_TEXT_COLOR` inconsistency** — three sites still hard-code
   `CssColor { r: 30, g: 30, b: 30, a: 255 }`:
   - `layout.rs:293` — `BoxType::Inline` fallback in `collect_inline_text()`
   - `render.rs:158` — `render_text()` (no-feather path)
   - `render.rs:219` — `render_text_scrolled()` (feather path)
   Anonymous boxes already use `CssColor::BLACK` from v0.7; the inconsistency
   means different code paths render text at different shades.

3. **`text-align` not implemented** — `center` and `right` keywords are parsed
   and stored in the property map but never read by the layout engine.

---

## Design

### Fix 1a — `CssColor::DARK` constant (`css.rs`)

Add alongside the existing `WHITE`, `BLACK`, `TRANSPARENT` constants:

```rust
pub const DARK: CssColor = CssColor { r: 30, g: 30, b: 30, a: 255 };
```

Replace every `CssColor { r: 30, g: 30, b: 30, a: 255 }` with `CssColor::DARK`:
- `layout.rs:293` — `BoxType::Inline` default in `collect_inline_text()`
- `render.rs:158` — `render_text()`
- `render.rs:219` — `render_text_scrolled()`

This is a purely mechanical substitution — behaviour is unchanged, naming is
now consistent with `CssColor::BLACK`.

### Fix 1b — `pen_x` f32 accumulation (`render.rs`)

Current code in `render_box()` (lines 107–111):

```rust
let mut pen_x = (origin_x + item.x) as i32;
for ch in item.text.chars() {
    let glyph = item_font.rasterize_cached(ch);
    blit_glyph(canvas, &glyph, pen_x, baseline_y, item.color);
    pen_x = pen_x.saturating_add(glyph.advance_width as i32);
}
```

Replacement:

```rust
let mut pen_x_f: f32 = origin_x + item.x;
for ch in item.text.chars() {
    let glyph = item_font.rasterize_cached(ch);
    blit_glyph(canvas, &glyph, pen_x_f.round() as i32, baseline_y, item.color);
    pen_x_f += glyph.advance_width;
}
```

`pen_x_f` accumulates fractional advances in f32; `round()` produces the
nearest pixel for each blit without discarding the sub-pixel remainder.
`saturating_add` is no longer needed: f32 cannot overflow for any realistic
document width.

### Feature — `text-align: center / right` (`layout.rs`)

#### New types

```rust
#[derive(Debug, Clone, Copy, Default, PartialEq)]
pub enum TextAlign { #[default] Left, Center, Right }
```

#### `InlineFormattingContext` gains `align`

```rust
pub struct InlineFormattingContext {
    pub font_size: f32,
    pub available_width: f32,
    pub align: TextAlign,
}
```

The `#[cfg(not(feature = "feather-renderer"))]` stub returns `(vec![], 0.0)`
unchanged; the struct field is compiled in both configurations.

#### Alignment shift in `flush_line!`

Inside the `#[cfg(feature = "feather-renderer")]` `layout` impl, replace the
existing `flush_line!` macro body with:

```rust
macro_rules! flush_line {
    () => {
        if !current_items.is_empty() {
            // Compute used width of this line.
            let content_w = current_items.last().map(|i| i.x + i.width).unwrap_or(0.0);
            let offset = match self.align {
                TextAlign::Left => 0.0,
                TextAlign::Center => ((self.available_width - content_w) / 2.0).max(0.0),
                TextAlign::Right  => (self.available_width - content_w).max(0.0),
            };
            if offset > 0.0 {
                for item in &mut current_items { item.x += offset; }
            }
            let lh = if cur_line_height > 0.0 { cur_line_height } else { 16.0 };
            let bl = if cur_baseline > 0.0 { cur_baseline } else { 12.8 };
            lines.push(LineBox {
                items: std::mem::take(&mut current_items),
                y: line_y,
                height: lh,
                baseline: bl,
            });
            line_y += lh;
            cursor_x = 0.0;
            cur_line_height = 0.0;
            cur_baseline = 0.0;
        }
    };
}
```

#### `layout_block()` reads `text-align`

In `layout_block()`, after extracting `font_size` and `color`, extract alignment
before constructing `InlineFormattingContext`:

```rust
let align = match &lb.box_type {
    BoxType::Block(s) | BoxType::Inline(s) => match s.properties.get("text-align") {
        Some(Value::Keyword(k)) => match k.as_str() {
            "center" => TextAlign::Center,
            "right"  => TextAlign::Right,
            _        => TextAlign::Left,
        },
        _ => TextAlign::Left,
    },
    BoxType::Anonymous => TextAlign::Left,
};
let ifc = InlineFormattingContext {
    font_size,
    available_width: lb.dimensions.content.width.max(1.0),
    align,
};
```

`text-align` is not in the inheritable set in `style.rs` for v0.8. It must be
explicitly set on the element whose text is to be aligned. (Inheritance of
`text-align` is deferred to a later version.)
